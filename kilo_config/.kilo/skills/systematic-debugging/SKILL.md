# 系统化调试

## 何时触发

- checker/reviewer 标记的阻塞问题需要修复
- 用户反馈"还是有问题/不对/遗漏"
- engineer 自测发现异常
- fixer 连续 2 轮同症状

## 信息收集模板（修复前必做）

1. **症状精确记录**
   - 输入：`[具体值或数据样本]`
   - 路径：`[函数/文件/行号]`
   - 输出：`[实际输出 vs 预期输出]`
   - 日志/错误码：`[完整消息]`

2. **变更溯源**
   - 上次成功版本：`[commit/时间]`
   - 本次失败版本：`[commit/时间]`
   - 之间变更：`[git diff 摘要]`

3. **环境快照**
   - 语言/运行时版本：
   - 关键依赖版本：
   - 相关配置值：

4. **最小复现**
   - 命令/输入：`[一条命令或一个最小输入]`
   - 复现率：`[每次/偶发（X%）]`

## 故障模式分类

| 维度 | 分类 | 优先排查方向 |
|------|------|-------------|
| 确定性 | 每次必现 | 代码逻辑、数据状态 |
| | 间歇性 | 竞态、缓存、外部依赖、时序 |
| 回归性 | 上次版本正常 | 最近变更（`git diff`） |
| | 历史也异常 | 需求层/架构层问题 |
| 影响面 | 单功能点 | 局部逻辑、边界条件 |
| | 多模块连锁 | 共享契约、配置、中间件 |

## 调试策略决策树

```
能否稳定复现？
  ├─ 否 → 优先怀疑：竞态/缓存/外部依赖
  │        策略：增加日志、隔离外部依赖、强制同步
  ├─ 是 → 是回归？
           ├─ 是 → 二分法回滚最近变更，定位引入 commit
           └─ 否 → 影响面？
                    ├─ 局部 → 单步调试/打印关键变量
                    └─ 系统 → 检查共享契约/配置/数据流
```

## 多假设验证

1. 写下所有可能的根因假设（至少 2 个）。
2. 对每个假设，设计一个**最小实验**来证伪它。
3. 优先验证"能最快证伪"的假设（奥卡姆剃刀）。
4. 一个假设被证伪后，记录原因，转向下一个。
5. 所有假设都被证伪 → 升级 reviewer，标记方法层失败。

## 根因确认标准

- 改 P 点，症状消失。
- 改 Q 点（无关点），症状保留。
- 回滚 P 点，症状复现。
- 三者都满足 → 根因确认；缺一 → 继续验证。

## 反模式

- `[DEBUG_ANTI_PATTERN_NO_REPRO]`：没有最小复现就改代码。
- `[DEBUG_ANTI_PATTERN_SHOT_IN_DARK]`：不改假设直接尝试多种修改。
- `[DEBUG_ANTI_PATTERN_NO_ROLLBACK]`：改后没验证回滚是否能复现问题。
