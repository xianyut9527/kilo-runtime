# ensemble

多执行器并行投票模式。用于高风险、多次失败或用户反馈不满意的任务。

## 执行流程

1. **coderAgent** 拆分子任务，生成委派包。
2. **executor-A/B/C** 并行执行同一子任务。
3. **synthesizer** 汇总 3 个执行器的输出，投票得出最终方案。
4. **coderAgent** 确认方案并交付。

## 投票规则

- 代码正确性优先：能通过验证的 > 不能通过的。
- 变动范围最小化：改动少的 > 改动多的（防 SCOPE_CREEP）。
- 与项目风格一致：符合现有代码风格的 > 引入新风格的。
- 边界覆盖完整：正常/空值/异常都处理的 > 有遗漏的。

## 触发条件

- T3 任务（安全/资金/权限/核心逻辑）
- 用户反馈"还是不对/有遗漏/不干净"
- 连续 2 次修复失败

## 输出

```
## 并行执行结果
| executor | 结论 | 支持理由 | 阻塞问题 |
|----------|--------|----------|----------|

## 投票结论
- 最终方案: executor-X
- 选择理由:
```
