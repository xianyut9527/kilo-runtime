1. 先识别问题类型：数据、UI/样式、交互、网络/接口、状态、性能，或其他。
2. 明确入口、目标行为、问题现象、复现条件和失败证据；缺失时先标注，不猜测补全。
3. 使用搜索和局部读取定位关键文件、关键符号和调用路径，优先沿问题类型对应的高优先级层排查。
4. 生成链路包，至少包含：
   - 问题类型
   - 入口与目标行为
   - 关键链路节点
   - 每层输入/输出或状态变化
   - 配置影响和外部依赖
   - 已确认异常点
   - 待证伪假设
   - 建议优先排查层与验证点
5. 输出时必须明确“先查哪一层、为什么先查这一层”，避免平均撒网。
6. 若链路中存在不确定点，明确标注而不是猜测补全；若尚未形成链路包，不建议直接修改。

## 默认排查顺序

- 数据类：`输入/参数 -> 数据源或请求 -> 解析/映射 -> 数据处理 -> 状态/缓存 -> 派生逻辑 -> 组件渲染`
- UI/样式类：`样式变量/主题 -> className/选择器 -> 布局容器 -> 条件渲染 -> DOM 结构 -> 数据回退`
- 交互类：`事件绑定 -> 处理函数 -> 状态更新 -> 副作用 -> 重新渲染`
- 网络/接口类：`请求触发 -> 请求参数 -> 认证/请求头 -> 响应状态 -> 响应解析 -> 下游状态`
- 状态类：`写入路径 -> store/context/cache -> 失效与同步 -> 派生状态 -> 订阅方/渲染`
- 性能类：`数据规模 -> 昂贵转换 -> 重复写入 -> 重渲染 -> 布局与重绘`
