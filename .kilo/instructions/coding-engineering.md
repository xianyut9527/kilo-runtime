# 编码工程化标准（coding-engineering）

> **沉淀进程序、不靠模型的编码工程能力。** 每次编码/审查自动注入。
> 原则：设计决策有据可依（模式决策表，不靠即兴）、组件化是默认（硬规则非可选）、优雅是硬标准（可检测非审美）。
> 普通模型照着本流程写 = 顶级工程输出。能力在程序里，不在模型里。
> 与 `docs/lessons/` 联动：本文件是**基线工程能力**（静态，人工沉淀）；lessons 是**积累的失败教训**（动态，自动晋级）。两者皆注入。

## 设计模式决策（先匹配情境，再写代码）

发现 ≥2 个分支按类型/状态/策略/实现分叉 -> **先想模式，不先写 if/else 长链**。

| 情境信号 | 选用模式 | 反模式（禁止） |
|---|---|---|
| 多算法/策略/规则切换、运行时选 | Strategy + 配置驱动 | if/else 长链硬编码分支 |
| 接口不兼容、对接第三方/遗留系统 | Adapter | 改调用方或被调方源码硬凑 |
| 对象创建复杂、多类型族、构造参数多 | Factory | 散落各处 `new` |
| 状态多、转换复杂、行为随状态变 | State | 字符串标志位 + switch |
| 事件广播、一对多解耦 | Observer / Pub-Sub | 调用方直接持有全部依赖 |
| 操作可组合、需可叠加 | Decorator / 组合 | 深继承链 |
| 复杂对象分步构建、多必选/可选参数 | Builder | 巨型构造函数（telescoping） |
| 统一接口多实现、按配置切换 | 策略接口 + 配置驱动 | 硬编码 `if type ==` |
| 跨层/跨域访问需收敛 | Facade / Repository | 调用方直接穿透多层 |

**YAGNI 守门**：模式只在分支数 ≥3 或明确预期增长时引入。用模式仅为"显得高级"是反模式--但分支已 ≥3 还硬写 if/else 是更严重的反模式。

## 组件化硬规则（默认抽，不是可选）

1. **≥2 处即抽象**：同一逻辑/样式/结构/数据访问/错误处理/日志/配置读取出现 ≥2 处 -> **必须**抽象为共享单元。grep/glob 命中 ≥2 即触发，不靠"感觉"。违反 -> `[LOCAL_PATCH]`/`[COPY_PASTE_FIX]`，verifier/reverse-auditor 必须 FAIL。
2. **抽象层级归位**：
   - UI 域 -> component / layout / design token / mixin / 全局 CSS
   - 逻辑域 -> util / hook / service / repository
   - 集成域 -> adapter / 策略接口 / 配置驱动 / 插件化
   - 跨域不混用（UI 抽象不进 util，反之亦然）。
3. **数据流单向、依赖方向符合分层**（ui->service->infra，不反向）；跨层直连禁止（ui 直连 infra、service 反调 ui）。
4. **公共 API/导出符号稳定，内部可变**；改动高扇入符号（被 ≥3 处调用）必须列影响清单写入 `risks`。
5. **依赖注入而非硬编码依赖**；副作用（IO/网络/状态/随机）收口在边界，核心逻辑保持纯函数可测。
6. **扩展点**：高频变更领域（表单/列表/权限/数据获取/第三方集成/错误处理/日志/配置）预留 slot/策略接口/配置驱动，不写死分支链。
7. **同批修改**：抽象变更必须同批同步所有消费者，禁止"先改一个看看"。

## 优雅编码硬标准（可检测，非审美）

- **命名**：表达意图，不缩写无义；函数动词、布尔 `is/has/can`、集合复数；领域概念用领域词不用技术词。
- **函数**：单一职责；≤40 行（超长拆）；参数 ≤4（多则聚合为配置对象）；无布尔参数（用语义方法或配置对象）。
- **控制流**：early return / guard clause 优先；嵌套 ≤3 层；无回调地狱（async/await）；无 `else` 在 return 之后。
- **数据**：immutable-first；无魔法数字/字符串（命名常量）；无重复字面量。
- **错误**：边界入参校验在入口；错误向上传播带上下文；不吞异常（catch 后必须处理或重抛带原因）；失败可重试的要幂等。
- **重复**：DRY 但不过度（≥2 处才抽，不为单处预抽象）。
- **可读性 > 巧妙；显式 > 隐式；纯函数 > 副作用。** 注释只留"为什么"，不写"在做什么"（在做什么应该由命名表达）。

## 反模式检测（coder 编码前自查 / reviewer 拦截）

| 反模式 | 检测信号 | 修正 |
|---|---|---|
| God object | 单类/文件 >300 行 或 >7 公共方法 | 按职责拆分 |
| 散弹手术（Shotgun Surgery） | 改一个需求要动 N 个分散文件 | 重新归集职责到一个单元 |
| 基本类型偏执 | 用裸 string/number 表示领域概念 | 提取值对象/类型 |
| 深嵌套 | if/for 嵌套 ≥3 层 | early return / 提取子函数 |
| 长参数列 | 参数 >4 | 聚合为配置对象 |
| 注释代偿 | 注释解释"这段做什么" | 重构到命名清晰 |
| 死代码/调试残留 | 注释掉的代码、console/print/debugger | 删除（交付前 scan-encoding + reverse-auditor 双查） |
| 重复实现 | 同段逻辑/样式 ≥2 处 | 组件化（见硬规则 1） |

## 落地流程（每次编码前过一遍，T1+ 硬门；T0 可简化但不得跳过落点识别）

1. **落点识别**：目标文件所属层 + 该层职责 -> 本次变更落点是否一致。跨层 -> 回 planner。
2. **依赖方向**：新代码 import/调用方向是否符合分层。反向 -> 停。
3. **复用优先**：grep/glob 扫描同类抽象。已有 -> 消费；无 -> 新建但标 `risks`。
4. **模式匹配**：≥2 分叉 -> 查模式决策表选模式。YAGNI 守门。
5. **组件化前摄扫描**：本次改动模式在代码库同类 ≥2 处 -> 强制组件化（硬规则 1）。
6. **影响面**：高扇入符号改动列影响清单。
7. **反模式自查**：上表逐项过。
8. **编码**：最小改动、遵循现有风格、优雅硬标准。
9. **改后**：grep 调用方确认兼容性。

> 违反任一项 -> 输出 `BLOCKED`/`NEEDS_CONTEXT`，由 conductor 判断是否回流 PLANNING。
