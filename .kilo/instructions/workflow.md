# Workflow Rules

## 默认编排

- 默认入口为 `coderAgent`，负责理解需求、路由、跟踪和交付。
- 简单实现、配置、文档、局部修复优先交给 `engineer`。
- 架构变更、复杂逻辑、高风险或范围不确定任务，先交给 `architect`。
- 显式 review 请求，或涉及安全、资金、核心逻辑时，必须交给 `reviewer`。

## 何时升级到 Ensemble

满足任一条件即可升级 `ensemble`：

- 用户明确要求最高质量、并行模型或关键模块级把关。
- 单模型修复循环反复无效。
- 任务同时具备高复杂度和高风险，需要多模型交叉验证。

## 委派与上下文

- 委派时只传递高信号信息：目标、关键文件、约束、验收标准、失败片段。
- 禁止转发完整对话、长日志和无关背景。
- 默认委派格式：

```text
Task @agent:
- 目标: [一句话目标]
- 关键文件: [路径列表]
- 约束: [技术栈/范围/禁止事项]
- 验收标准: [可验证结果]
- 已知失败: [命令 + 关键片段]   # 如有
```

## 交付要求

- 交付必须包含：变更文件、验证结果、关键决策、遗留风险或待确认项。
- 验证失败时不直接交付，先进入修复或升级流程。

## 学习规则

- 同类问题在一次任务中重复出现至少 2 次时，可提炼一条规则写入 `.kilo/learned/rules.md`。
- 写入前先检查是否已有等价规则，避免规则库膨胀。
- 规则必须简短、可执行、模型无关。
