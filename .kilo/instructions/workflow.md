# Workflow Rules

## 默认编排

- 默认入口为 `coderAgent`，负责理解需求、路由、跟踪和交付。
- 简单实现、配置、文档、局部修复优先交给 `engineer`。
- 架构变更、复杂逻辑、高风险或范围不确定任务，先交给 `architect`。
- 显式 review 请求，或涉及安全、资金、核心逻辑时，必须交给 `reviewer`。
- 涉及调用链、数据流、状态流、配置流、根因不明确或用户明确要求“排查/定位/分析”的问题，默认先进入 `trace-first` 流程。

## Trace-First

- 以下场景默认先 `trace`，未形成链路包前不直接修改：
  - 数据异常、状态异常、交互失效、接口异常、性能异常；
  - 跨模块、多文件、链路长或配置影响明显；
  - “还是不对”“有遗漏”“链路有问题”“先分析原因”这类用户反馈。
- `trace-first` 的输出必须至少包含：
  - 问题类型；
  - 入口与目标行为；
  - 关键链路节点；
  - 每层输入/输出或状态变化；
  - 已确认异常点与待证伪假设；
  - 建议优先排查层和验证点。
- 若缺少复现条件、失败证据或关键上下文，先补证据，不带着关键假设直接修改。

## 何时升级到 Ensemble

满足任一条件即可升级 `ensemble`：

- 用户明确要求最高质量、并行模型或关键模块级把关。
- 单模型修复循环反复无效。
- 任务同时具备高复杂度和高风险，需要多模型交叉验证。
- 链路跨多个层次，且高优先级排查层存在多个可疑点，单模型难以稳定收敛。
- 用户表达强调性/质疑性/烦躁性语言，暗示之前的修复多次不完整或不正确（如"还是不对""改了很多次""深度分析""还有遗漏"等），coderAgent 应识别并自动升级。

## 委派与上下文

- 委派时只传递高信号信息：目标、关键文件、约束、验收标准、失败片段。
- 禁止转发完整对话、长日志和无关背景。
- 若项目内存在项目级 `AGENTS.md`、`.kilo/skills/` 或 `.kilo/commands/`，优先把它们视为项目知识来源；全局规则只做兜底。
- 对排查类任务，额外传递：问题类型、已定位链路、上游/下游优先级、已排除层、剩余可疑层。
- 默认委派格式：

```text
Task @agent:
- 目标: [一句话目标]
- 关键文件: [路径列表]
- 约束: [技术栈/范围/禁止事项]
- 验收标准: [可验证结果]
- 已知失败: [命令 + 关键片段]   # 如有
```

## 交付要求

- 交付必须包含：变更文件、验证结果、关键决策、遗留风险或待确认项。
- 验证失败时不直接交付，先进入修复或升级流程。
- 对 bug 或排查类任务，交付时必须说明：最终命中的问题层、为何不是其他层、如何证明根因已闭合。
