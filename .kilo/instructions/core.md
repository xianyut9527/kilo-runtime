# Core Runtime Rules

## [META] 行为框架
先定位后修改、先复用后新建、先确认后动手；最小改动，不做投机扩展。

## 语言与意图
- [MUST] 始终使用用户提问语言回复；纠正明显错别字后再执行并简要标注。
- [MUST] 咨询类请求（"分析一下""给个建议""怎么优化""评价""能不能"等）只输出结论/方案，**禁止修改任何文件**。
- [MUST] 执行类请求（"修复""实现""添加""删除""帮我改"等）按正常流程编码。
- [MUST NOT] 基于猜测编码：需求歧义/信息缺失/置信度不足时，先一次性澄清。
- [PREFER] 先说假设与可选方案再实现，优先选择更简单路径。
- 边界模糊时先输出分析并询问"是否需要我直接实施？"；用户明确"不要改代码"时严格遵守。

## 实施与复用
- [MUST] 编码前搜索现有实现；覆盖≥80%需求时直接复用或在原处扩展，禁止重复实现。
- [MUST] 只做最小改动，保持项目既有风格与分层；禁止顺手重构、投机扩展或为未来预埋抽象。
- 工具/状态/接口/视图逻辑按项目现有分层归位；无约定时遵循"低耦合、单一职责、易复用"。
- 涉及链路不明确的问题，先定位再修改。

## 删除与清理完整性

[MUST] 删除任何内容（文件/目录/模块/配置项/功能/接口/依赖/章节）后，必须执行完整性扫描：

1. **全局符号搜索**：用被删项的关键词汇（文件名、路径片段、配置键、函数名、变量名）通过 `grep` 全仓库搜索，确认无遗漏引用
2. **关联文件检查**：安装脚本、CI/CD 配置、构建配置中的排除列表/复制列表/条件判断是否引用了被删项
3. **编号结构修复**：删除编号型条目（步骤、列表项、章节号）后，检查并修正后续编号，同时修正所有指向这些编号的内部引用
4. **主动输出遗漏清单**：将所有发现的残留引用列出来，询问用户是否一并清理，禁止默认无视

## 项目探测

[MUST] 进入陌生项目时依次探测：
1. 通过构建配置推断语言、框架与包管理器。
2. 定位入口文件与关键目录，识别项目边界与模块组织。
3. 扫描关键符号（导出/类型/接口/函数签名），构建符号索引辅助复用与定位。
4. 推断构建/测试/Lint 命令，确认命令可用后纳入自测流程。
[PREFER] 探测结果按优先级注入上下文：入口与关键符号 > 构建配置 > 边缘文件。

## 诊断优先级
[MUST] 先判断问题类别，沿对应链路逐层下钻，未排除上游前不修改下游。

| 类别 | 排查链路 | 信号（粗体为区分特征） |
|------|---------|----------------------|
| 数据 | 输入/参数→数据源→解析/映射→过滤/聚合→状态/缓存→派生→渲染 | 展示值/统计与预期不符；**接口返回正常但页面仍错**；过滤/排序/格式化后异常 |
| UI/样式 | 样式变量/主题→className→布局→条件渲染→DOM→数据回退 | 错位、遮挡、间距异常；**主题不生效、视觉状态不一致**；同数据不同环境表现不同 |
| 交互 | 事件绑定→处理函数→状态更新→副作用→重渲染 | 点击/提交无反应；**按钮/弹窗/表单状态不随操作更新** |
| 网络/接口 | 请求触发→参数/载荷→认证→响应→解析→下游状态 | HTTP错误码(401/403/500)、请求失败；**接口成功(200)但字段缺失或格式异常** |
| 状态 | 写入→store/context/cache→失效同步→派生→订阅/渲染 | 展示旧数据、缓存污染；**刷新后异常消失**(区别于数据源)；局部更新不同步 |
| 性能 | 数据规模→昂贵转换→重复状态写入→重渲染→布局重绘 | 操作卡顿、CPU飙升；**输入响应延迟、滚动抖动、频繁无效重渲染** |

### 易混淆类别快速锚定

| 混淆对 | 锚定问题 | 判定方向 |
|--------|---------|---------|
| 数据 vs 网络 | 接口是否返回错误码？ | 有错误码 → 网络；200但展示错 → 数据 |
| 数据 vs 状态 | 刷新后问题是否消失？ | 依旧 → 数据；消失 → 状态 |
| 交互 vs 状态 | 操作后数据层是否正确？ | 数据对但UI不更新 → 交互；数据就不对 → 状态 |
| 性能 vs 状态 | 卡顿是否伴随重复请求/渲染？ | 有 → 状态(重复写入)；无 → 性能(渲染瓶颈) |

[PREFER] 默认不先怀疑组件/UI层，仅在上游基本正常时提高其优先级。

## 验证与安全
- [MUST] 修改后执行可用的测试、构建、类型检查、Lint；格式化仅限变更文件。
- [MUST NOT] 暴露密钥/Token/API Key；敏感配置通过环境变量注入。
- [MUST] 涉及资金、安全或核心逻辑的变更必须经过独立审查。

## 大文件
[MUST] 先搜索定位、局部读取；优先增量编辑，禁止整文件重写。
