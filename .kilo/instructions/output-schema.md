# Output Schema（统一交付输出规范）

## 1. 总则

### 1.1 目的

kilo_config 下游消费方（`experience-ranker` / `feedback-collector` / 未来的 review 自动化工具）需要从各 agent 的交付文本中**结构化地抽取**三类高价值信号：

1. **结论** —— 任务是否完成、通过 / 失败 / 有条件通过。
2. **阻塞问题** —— 明确指向文件位置和证据的问题清单。
3. **证据片段** —— 命令输出、代码路径、测试结果等可追溯引用。

为了在不抹平各 agent 业务差异（engineer 强调验收映射，checker 强调动态验证，reviewer 强调三视角，fixer 强调根因回传）的前提下满足以上抽取需求，本文件定义：

- **最小公共字段**：所有 agent 必须输出的 3 个字段。
- **位置约定**：这些字段在交付文本中的可预测位置。
- **标记语言规范**：`[MARKER]` 与状态枚举的写法。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **最小公共集** | 只统一下游必须解析的字段，不强制分区标题、分区顺序。 |
| **可预测位置** | 结论必须在开头，阻塞问题在中段，证据片段就近引用。 |
| **向后兼容** | 既有 `agent/*.md` 中的输出模板继续有效，本文件只追加约束，不删除既有分区。 |
| **可机器解析** | 字段标题必须是固定中文字符串；不得使用 `结果:` / `结论：` / `**结论**` 等变体。 |
| **最小惊讶** | 字段名沿用各 agent 现有用语（`验证结论` / `审查结论` / `修复结果`），不强行统一为单一标题。 |

### 1.3 不在本规范范围

- 各 agent 的**业务分区**（需求理解、变更摘要、专审视角、修复策略等）—— 由各 agent 自行维护。
- 验证命令的**具体内容** —— 由各 agent 根据任务决定。
- **正文叙述** —— 自由格式，仅供人类阅读。
- SKILL.md / MEMORY.md 的 frontmatter 格式 —— 见 `agent/engineer.md`「SKILL.md frontmatter 识别」与 `agent/checker.md`「skills frontmatter 合规检查」。

## 2. 通用字段表

下表列出**所有 agent 交付输出都必须包含**的最小公共字段。字段标题在交付文本中**必须逐字出现**（含中文冒号或半角冒号皆可，但需与解析器约定一致；推荐中文全角冒号 `：`）。

| 字段名 | 含义 | 必含 | 出现位置 | 取值规范 |
|--------|------|------|----------|----------|
| **结论** | 任务最终状态 | ✅ | 交付文本最前部（紧随 `## 结论` 标题） | 枚举：`PASS` / `FAIL` / `有条件通过` / `未完成` / `通过` / `不通过`；多 agent 中由各 agent 选择最贴近自身语义的取值（详见 §3） |
| **阻塞问题** | 未解决的 blocker 列表 | ✅ | 结论之后、变更摘要之前 | 列表；每条格式：`[严重/警告] [文件:位置] [问题] → [修复建议] \| 证据:[片段]`。无阻塞时显式写 `无` 或留空 |
| **证据片段** | 与结论/问题配对的命令输出、代码路径、测试结果 | ✅ | 紧跟所属字段（阻塞问题行的 `\| 证据:` 段、动态验证行的 `\| 证据:` 段） | 行内片段 ≤ 200 字符；超长截断并标注 `[TRUNCATED]` |
| **覆盖矩阵** | 验收标准 → 实现位置 → 验证方式 → 边界覆盖 → 状态 | ⚪ agent 自决 | engineer 强制；checker / reviewer 在涉及验收标准时强制 | Markdown 表格，列固定 |

> 说明：`⚪` 表示该字段在该 agent 中**默认强制**，但在不需要时（如 fixer 不直接交付验收标准）可省略。`✅` 表示**所有 agent 无条件必须**。

### 2.1 字段间的因果关系

```text
结论 ── 派生自 ──> 阻塞问题 + 覆盖矩阵
                  └─ 证据片段
```

- `结论` 的取值必须能从 `阻塞问题` 是否非空、覆盖矩阵是否全部 `状态: ✅` 推导出来，二者不一致时 `结论` 优先并标注 `[INCONSISTENT]`。
- `证据片段` 不得悬空：每条都必须能被某个 `结论` / `阻塞问题` / `覆盖矩阵` 行的引用反查。

## 3. 各 agent 最小输出模板

下表列出每个 agent 必须满足的最小约束。各 agent 的详细业务分区由 `agent/<name>.md` 定义，本规范**不覆盖**其内容。

### 3.1 engineer

| 字段 | 必须 | 标题字面量 | 说明 |
|------|------|-----------|------|
| 结论 | ✅ | `## 前提条件（必填）` 前的最后一个状态标记 | 工程师不自验，**不输出** PASS/FAIL；改用 `等待 checker 验证` |
| 阻塞问题 | ⚪ | `## 遗留风险` | 工程师的遗留风险即"非阻塞但需关注"；真正的 blocker 由 checker 标记 |
| 证据片段 | ✅ | `## 验证` 行内 `\| 证据:` 段 | 命令 + 结果片段 |
| 覆盖矩阵 | ✅ | `## 验收映射表（强制）` | 列固定：`验收标准 \| 实现位置 \| 验证方式 \| 边界覆盖 \| 状态` |

最小骨架（与 `agent/engineer.md` 第 91-124 行兼容）：

```text
## 需求理解
- ...

## 变更摘要
- ...

## 验收映射表（强制）
| 验收标准 | 实现位置 | 验证方式 | 边界覆盖 | 状态 |
|----------|----------|----------|----------|------|

## 验证
- 测试/构建/类型/Lint: [命令] → [结果] | 证据:[片段]

## 遗留风险
- [风险或待确认项]

## 前提条件（必填）
- [ ] ...

（末尾）等待 checker 验证
```

### 3.2 checker

| 字段 | 必须 | 标题字面量 | 说明 |
|------|------|-----------|------|
| 结论 | ✅ | `## 验证结论` | 枚举：`PASS` / `FAIL` |
| 阻塞问题 | ✅ | `## 阻塞问题` | 列表格式见 §2 |
| 证据片段 | ✅ | `## 动态验证` 与 `## 阻塞问题` 行内 `\| 证据:` 段 | 命令输出片段 |
| 覆盖矩阵 | ✅ | `## 覆盖检查` | 列固定：`验收标准 \| 实现位置 \| 验证方式 \| 边界覆盖 \| 状态` |

最小骨架（与 `agent/checker.md` 第 89-118 行兼容）：

```text
## 验证结论
[PASS / FAIL]

## 动态验证
- 测试/构建/类型/Lint: [命令] → [结果] | 证据:[片段]

## 覆盖检查
| 验收标准 | 实现位置 | 验证方式 | 边界覆盖 | 状态 |
|----------|----------|----------|----------|------|

## 执行路径核查
- ...

## 同类点检查
| 同类点 | 扫描证据 | 发现来源 | 覆盖状态 | 结论 |

## 范围与映射
- 缺失/越界/无关修改/OUT_OF_SCOPE: ...

## 阻塞问题
- [严重/警告] [文件:位置] [问题] → [修复建议] | 证据:[片段]

## 声明核实
- ...
```

### 3.3 reviewer

| 字段 | 必须 | 标题字面量 | 说明 |
|------|------|-----------|------|
| 结论 | ✅ | `## 审查结论` | 枚举：`通过` / `有条件通过` / `不通过` |
| 阻塞问题 | ✅ | `## 问题清单` | 列表格式见 §2 |
| 证据片段 | ✅ | `## 问题清单` 行内 `\| 证据:` 段 | 代码引用片段 |
| 覆盖矩阵 | ⚪ | `## 覆盖检查`（涉及验收标准时） | 与 checker 共享表头 |

最小骨架（与 `agent/reviewer.md` 第 102-115 行兼容）：

```text
## 审查结论
[通过 / 有条件通过 / 不通过]

## 专审视角
- 安全: [通过/有问题/未涉及]
- 架构: [通过/有问题/未涉及]
- 简化: [通过/有问题/未涉及]

## 问题清单
- [严重/警告] [文件:位置] [问题] → [建议] | 证据:[片段]
```

### 3.4 fixer

| 字段 | 必须 | 标题字面量 | 说明 |
|------|------|-----------|------|
| 结论 | ✅ | `## 修复结果` | 枚举：`已修复` / `未修复/阻塞` / `有条件修复` |
| 阻塞问题 | ✅ | `## 修复结果` 中 `未修复/阻塞:` 子项 | 列表 |
| 证据片段 | ✅ | `## 修复结果` 中 `验证:` 子项 | 命令 + 结果 |
| 覆盖矩阵 | ⏸ 不适用 | —— | fixer 不直接对应验收标准 |
| 根因回传 | ✅ | `## 根因回传（强制）` | 必须包含根因层 / 修复点 / 同症状复发判断 |

最小骨架（与 `agent/fixer.md` 第 34-68 行兼容）：

```text
## 修复策略
- 问题:
- 改哪:
- 怎么改:
- 对应验收标准/同类点:

## 修复结果
- 已修复: ...
- 未修复/阻塞: ...        ← 阻塞问题在此
- 验证: [命令] → [结果] | 证据:[片段]
- 影响范围: ...

## 资源清理确认
- [ ] 已清理 ...

## memory / skills 修复约束
- ...

## 根因回传（强制）
- 根因层: 执行层 / 方法层 / 需求层
- 本次修复点: [文件:行号] [改动摘要]
- 是否同症状复发: 是 / 否
```

## 4. 标记语言规范

### 4.1 状态 marker

| 标记 | 含义 | 使用 agent |
|------|------|-----------|
| `[PASS]` | 验证通过 | checker |
| `[FAIL]` | 验证失败 | checker |
| `[通过]` / `[有条件通过]` / `[不通过]` | 审查结论 | reviewer |
| `[已修复]` / `[未修复]` / `[有条件修复]` | 修复状态 | fixer |
| `[MISSING_ACCEPTANCE_MAP]` | 验收映射表缺失 | checker 判定 |
| `[FAKE_CONTEXT]` | 已读取文件清单含虚假/无关路径 | checker 判定 |
| `[SCOPE_CREEP]` | diff 中存在验收标准未声明的改动 | checker 判定；reviewer 自动二检不重复检测 SCOPE_CREEP（见 workflow.md 自动二检条款） |
| `[OUT_OF_SCOPE]` | 越界修改 | checker 判定 |
| `[PROCESS_VIOLATION]` | 流程日志缺步或行为漂移 | 任意 agent 判定 |
| `[UNCLEANED_ARTIFACT]` / `[FOUND_ORPHAN_ARTIFACT: 路径]` | 临时文件未清理 | 任意 agent 判定 |
| `[INCONSISTENT]` | 结论与阻塞问题/覆盖矩阵不一致 | 下游解析器追加 |
| `[TRUNCATED]` | 证据片段超长截断 | 任意 agent 追加 |
| `[UNVERIFIED]` | 验收标准只有文字描述无代码路径 | checker 判定 |
| `[UNCOVERABLE_REQUIREMENT]` | 需求扩散包中无法覆盖的项 | 任意 agent 判定 |
| `[RECOVERED_FROM_INSTRUCTIONS]` | 上下文压缩后从 instructions 恢复 | 任意 agent 追加 |
| `[ROLLBACK]` | 验证变差时回滚本轮改动 | fixer 追加 |
| `[SKILL_FRONTMATTER_INVALID]` | SKILL.md frontmatter 不合规 | checker 判定 |
| `[PATH_DEVIATION]` | 定级路径与实际路径不一致 | checker 判定 |
| 安全 GAP | `[SECURITY_GAP_SQL_INJECTION]` / `[SECURITY_GAP_XSS]` / `[SECURITY_GAP_COMMAND_INJECTION]` / `[SECURITY_GAP_PATH_TRAVERSAL]` / `[SECURITY_GAP_PLAINTEXT_PASSWORD]` / `[SECURITY_GAP_WEAK_HASH]` / `[SECURITY_GAP_NO_HASH]` / `[SECURITY_GAP_NO_RATE_LIMIT]` | checker 判定 |
| 性能 GAP | `[PERF_GAP_NO_LIMIT]` / `[PERF_GAP_NO_UPLOAD_LIMIT]` / `[PERF_GAP_NO_BATCH_LIMIT]` | checker 判定 |

### 4.2 写法规则

1. **大小写敏感**：所有 marker 全大写，下划线分隔。
2. **就近引用**：marker 必须紧贴其引用的代码位置或问题行，不允许堆在文末。
3. **路径格式**：`文件:行号` 或 `文件:行号-行号`；行号缺失时使用 `文件:函数名`。
4. **证据前缀**：所有证据片段使用 `| 证据:` 前缀，**不要** 用 `证据:` / `Evidence:` 等变体。
5. **空值显式化**：当某字段无内容时，写 `无` 或 `N/A`，**不要** 省略整行。
6. **嵌套 marker**：允许 `[[PARENT:CHILD]]` 形式表达层级（如 `[[SECURITY_GAP:SQL_INJECTION]]`），但默认扁平。
7. **不允许中英文混用大小写**：`[Pass]` / `[fail]` / `[已pass]` 均视为非法。

### 4.3 解析器提示（给 experience-ranker 等下游）

```text
# 推荐抽取逻辑
1. 扫描 `## 结论` / `## 验证结论` / `## 审查结论` / `## 修复结果` 标题，提取结论值
2. 扫描 `## 阻塞问题` / `## 问题清单` / `## 遗留风险` / `## 修复结果` 中 `未修复/阻塞:` 子项，提取问题列表
3. 用正则 `\| 证据:([^|]+)` 抽取证据片段
4. 用 markdown 表格解析器识别 `## 验收映射表` / `## 覆盖检查` / `## 同类点检查` 表格
5. 用正则 `\[([A-Z_]+(?::[A-Z_]+)?)\]` 抽取所有 marker，归类到 §4.1 表
```

## 5. 版本与变更

- v1（当前）：定义最小公共字段、位置约定、marker 规范，与既有 `agent/*.md` 输出模板完全兼容。
- 后续变更必须：
  1. 在 PR 中列出新增/删除的 marker 及其在 §4.1 表中的对应行。
  2. 不删除既有 marker；如需作废，标注 `[DEPRECATED]` 并保留至少 1 个版本周期。
  3. 不修改各 agent 的业务分区标题字面量（`## 需求理解` / `## 变更摘要` 等），仅在本规范中追加约束。
