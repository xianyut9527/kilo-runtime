# 反思与错误恢复

## 三层判定
- **执行层**：路径、语法、命令、工具用法错误。直接修正，不计重试。
- **方法层**：实现策略不对、同类错误反复、修复引入新问题。换策略重试，最多 2 次。**连续 2 轮 fixer 命中同症状 → 自动判定方法层失败，直接升级 reviewer，不再继续 fixer（见 workflow-core.md#同症状防空转）。**
- **需求层**：目标不清、需求理解可能错误、关键假设无法验证。暂停问用户，禁止猜测编码。

### memory 回溯

当同类错误反复出现时，优先读取 `MEMORY.md` 确认是否为已知陷阱，避免重复踩坑。

若错误模式未在 MEMORY.md 中记录，触发 `skills-writer` 评估是否应写入 MEMORY.md。

## 反馈格式
方法层失败必须输出可复用反馈：

```text
错在哪: [位置 + 表现]
为什么错: [原因]
怎么改: [下一步动作]
原则: [以后避免同类问题的规则]
```

## Circuit Breaker
- 连续 3 次仍无法收敛时停止自动重试。
- 输出：问题定位、已尝试方案、失败原因、下一步选项。
- 未获用户确认前不得继续同一失败路径。

## 推测与验证
- 可疑但未验证的路径标记为 `[SPECULATIVE]`，不据此做代码修改。
- 交付物中涉及推测的部分必须显式标注，不得混同于已验证结论。

### memory 引用规范

交付物中引用 `MEMORY.md` 或 `USER.md` 的约束时，必须标注：

- 来源文件路径
- 具体条目标题或锚点
- 引用条目是否经过 reviewer 验证

格式：`MEMORY.md#<条目锚点>: <摘要>`
