# Guardrails（负面约束速查）

1. 不要在未判定 INQUIRY/EXECUTION 前开始任何分析或修改。
2. 不要在未输出 [TIER: Tn] 理由前调用任何 subagent。
3. 不要在未附验收映射表+已读文件清单前声称完成。
4. 不要在未定义边界条件与失败语义前开始编码。
5. 不要在未显式校验外部输入类型/长度/格式前进入业务逻辑。
6. 不要在未覆盖错误路径/边界/空输入前停止测试。
7. 不要在未 profile 前优化任何代码。
8. 不要在根因调查完成前提议修复。
9. 不要在重构后未运行全量测试确认行为不变。
10. 不要在未核对安全项前批准 PR。
11. 不要把用户输入直接传给解释器（SQL/Shell/浏览器）。
12. 不要在错误响应中暴露可被攻击者利用的实现细节。
13. 不要在文档中描述"是什么"而应解释"为什么"。
14. 不要把当前实现细节当作真实需求。
15. 不要让一个类/模块有多于一个变更理由（SRP）。
16. 不要让函数对同一输入返回不同结果（避免隐式状态依赖）。
17. 不要用复制粘贴消除重复——提取共享抽象（DRY）。
18. 不要把临时调试代码（print/console.log）留在提交中。
19. 不要吞掉异常（空 catch）——至少记录并向上传播。
20. 不要用返回值表示错误而不在类型中显式标注。
21. 不要在未确认函数"应抛什么错"前断言其成功。
22. 不要在未量化前后指标前宣称优化成功。
23. 不要把"能跑一次"或"用了巧技"当成完整构造。
24. 不要在未确认项目既有命名风格前引入新风格。
25. 不要在未检查是否遵循编码标准前合并。
26. 不要凭感觉评审——使用固定 checklist。
27. 不要从风格开始审——安全永远第一。
28. 不要橡皮图章 AI diff——逐行读。
29. 不要在一次重构中混合多个独立变更。
30. 不要把重构与新功能开发混在同一提交。
31. 不要在未建立特征化测试前修改遗留代码。
32. 不要提交不符合 Conventional Commits 规范的提交信息。
33. 不要让一个提交包含多个无关变更。
34. 不要在改文件前不看 git status。
35. 不要把技术书整本喂模型——按语义单元 chunk。
36. 不要把 AGENTS.md 当静态——持续迭代。
37. 硬 token 预算——每个循环设上限（per_loop_max=160K，per_agent_prompt_max=1500，per_agent_return_max=2000）。
38. 每条规则必须引用它关闭的真实失败模式，而非偏好。
39. 把会话中艰难得到的"黄金路径"收割成可复用 skill/规则。
40. 从 PR 评审评论提取编码规则并生成 AGENTS.md。
41. 完成前跑相关测试/检查——不要假设。
42. 完成前自检：读者能否本地跟随此变更？名字/API 是否无需叙述即承载含义？变更是否显式且快乐路径仍清？框架/持久化/厂商/构造细节是否留在边界后？是否从触碰区移除至少一个坏味？测试是否保护了变更的行为/契约？
43. 上下文压缩后检测并注入提醒重读 AGENTS.md——防长会话压缩后规则失忆。
44. 禁止同一响应内并行发起多个 task。
45. 禁止在 task 发起瞬间到 result 返回前输出任何文字或调用其他工具。
46. 禁止 subagent 返回 >2000 字符完整报告。
47. 禁止用整文件 read 喂主会话 context。
48. 禁止凭记忆维护系统状态——把派生上下文持久化。
49. 禁止给进程/服务超过其需要的权限——最小权限原则。
50. 不要在代码里硬编码密钥。
