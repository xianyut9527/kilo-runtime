# 输出详细度标准

> 本文件为所有 agent 的统一输出质量标准，与各 agent 自身模板互补。如有冲突，agent 自身模板优先。

## 通用输出要求

- 变更描述必须包含：修改了什么函数/逻辑、为什么这样改、影响了什么
- 禁止使用"优化了代码""修复了问题""调整了逻辑"等模糊表述，必须具体说明
- 涉及 bug 修复时，必须写清楚：根因是什么、修复方式是什么、如何验证修复有效
- 涉及新增功能时，必须写清楚：新增了什么能力、入口在哪里、如何触发

## 代码级细节要求

- 修改超过 5 行逻辑的函数/方法，需在变更摘要中描述逻辑流转变化
- 新增函数/组件需说明输入输出契约（参数、返回值、副作用、异常）
- 删除代码需说明为什么该代码不再需要（是已迁移、已废弃、还是冗余）
- 修改接口/类型/配置需说明向后兼容性（是否破坏现有调用方）

## 验证结果要求

- 测试结果必须包含通过数/总数（如 `12/15 passed, 3 failed`）
- 失败项必须列出具体用例名和关键错误信息（至少前 3 行错误栈）
- 无法运行的验证项必须标记 `[SKIPPED]` 并说明原因（如"无测试框架""环境缺失"）
- 不可标记为 `[VERIFY_PENDING]` 后直接交付——必须说明阻塞原因

## 决策记录要求

- 凡涉及"在两种以上可行方案中做选择"的，必须在输出中记录：
  - 考虑了哪些备选方案
  - 为什么选择当前方案
  - 被排除方案的风险是什么
- 凡涉及复用现有代码的，必须标注：复用了哪个文件/函数、是否做了扩展

## 范围控制要求

- 凡修改了需求未明确要求的文件，必须在变更摘要中标注 `[范围外]` 并说明原因
- 凡因技术约束不得不连带修改的文件，必须在变更摘要中标注 `[连带修改]` 说明依赖关系
