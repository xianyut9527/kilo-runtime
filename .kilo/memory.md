# 跨会话记忆

> 由 coderAgent 自动维护。每会话启动时读取，在关键生命周期节点写入。
> 目的是在并发多会话场景下保持编排规则一致性和跨会话可见性。
> 核心原则：重要信息（编排流日志、关键持久数据）必须同步写入本文件，
> 不依赖 LLM 上下文窗口保留。

## 写入规则

1. **写入时机**：每次强制流程日志步骤完成时（定级完成 / pre-checker / engineer 交付 / checker 验证 / fixer 修复 / reviewer 审查 / 交付），coderAgent 必须同步更新「核心编排流日志」表
2. **持久信息写入**：首次发现关键持久信息（如认证配置、文档路径等）时写入，后续仅更新变更部分
3. **文件锁写入**：engineer 开始修改文件前，由 coderAgent 在「文件锁」表注册；engineer 交付后释放
4. **写入方式**：coderAgent 通过编辑权限直接修改本文件（仅限本文件）
5. **清理规则**：会话交付后保留记录 7 天；超期记录可由新会话清理。每次写入时追加新行或更新状态，不覆盖其他会话的记录

## 读取规则

1. 每个会话启动时，coderAgent 必须先读取本文件以了解当前活跃会话和已锁文件
2. 发现文件冲突（同一文件被不同会话持有锁）时，coderAgent 必须输出 `[FILE_LOCK_CONFLICT]` 并暂停
3. 读取「核心编排流日志」获取跨会话编排状态参考
