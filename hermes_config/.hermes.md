# 编码工作区规则

## 强制锚点

1. 意图判定优先：咨询类只分析不改文件；执行类才编码。
2. 定级前置：安全敏感词 → 最低 T2。
3. 流程违规即停：跳步标 `[PROCESS_VIOLATION]` 并暂停。
4. 临时文件写入系统临时目录，禁止污染项目目录。

## 安全约束

⚠️ 禁止写入 API Key / Token / 密码 / 凭证 / 内部域名 / IP / PII 到版本控制文件。

## 编码前检查点

调用 `patch`/`write_file` 前必须完成：
1. `search_files` 搜索目标符号定义和引用
2. `search_files` 搜索同类平行实现
3. **如有已知符号**：`gitnexus_context` 查调用链 + `gitnexus_impact` 查影响面
4. **如涉及表变更**：`gitnexus_data_impact` 确认数据层影响

未执行 → `[CHECKPOINT_MISSED]`。

**工具优先级**：`gitnexus_*` > `search_files` > `read_file`

## gitnexus 优先场景

| 场景 | 工具 | 优势 |
|------|------|------|
| 找符号调用方 | `gitnexus_context` | 精确 + 间接调用 |
| 分析影响面 | `gitnexus_impact` | 深度优先，不漏网 |
| 数据层影响 | `gitnexus_data_impact` | 从表反向推控制器 |
| 提交前扫描 | `gitnexus_detect_changes` | diff → 符号自动匹配 |
| API 形状验证 | `gitnexus_shape_check` | 响应键 vs 消费者访问键 |

## session_search 强制触发

以下场景必须主动调用 `session_search`：
1. 用户说"又出问题了"/"还是不对"/"跟上次一样"
2. 同一类错误连续出现 2 次
3. 配置文件修改后解析失败

未搜索 → `[NEEDS_RECALL]`。

## 编码后验证

每次 `patch`/`write_file` 后立即执行：
1. **语法**：`python -m py_compile` / `node --check` / 对应 linter
2. **测试**：`pytest -x` / `npm test`（如有）
3. **diff**：`git diff --stat` 确认改动范围

验证失败 → 立即修复。

## 全自动经验回写（无条件触发）

任务结束后**不询问**，自动执行：

```
提取 → 路由
- 用户偏好 → memory(target='user')
- 项目约定 → skill_manage(project-knowledge)
- 可复用模式 → skill_manage(patterns)
- 应当避免 → skill_manage(anti-patterns)
- 规则冲突 → 标记 [RULE_CONFLICT]，不覆盖
```

**禁止编造未验证经验**。
