# 编码工作区规则

## 强制编排锚点

1. **意图判定优先**：任何任务先判定「咨询类 / 执行类」。咨询类只分析不改文件；执行类才进入后续流程。
2. **执行类三段开场白**：意图判定 → 任务定级（T0-T3）→ 强制流程日志（≥7 节点），然后才可调用修改性工具。
3. **定级前置**：命中安全敏感关键词（user/auth/payment/wallet）→ 最低 T2。
4. **单元闭环**：T1+ 任务拆为可验证小单元，每单元独立 engineer → checker → fixer 闭环。
5. **验收必附映射表 + 已读取文件清单**：缺则 `[MISSING_ACCEPTANCE_MAP]` / `[FAKE_CONTEXT]` FAIL。
6. **SCOPE_CREEP**：checker L2 反向核对 diff，命中即 FAIL。
7. **自验无效**：engineer 不得自验，必须过 checker 客观验证。
8. **skills / 自进化合规**：任务启动加载 `SOUL.md` + `.hermes.md` + `skills/`；方法层/需求层失败触发跨会话根因回溯（`session_search` + `search_files` + `read_file`）。
9. **流程违规即停**：发现跳步立即标 `[PROCESS_VIOLATION]` 并暂停。
10. **临时文件**：写入系统临时目录，禁止污染项目目录。

## 安全约束

⚠️ 禁止写入 API Key / Token / 密码 / 凭证 / 内部域名 / IP / PII / NDA 内容到任何版本控制文件。

## 子代理委派策略

| 角色 | 时机 | toolsets |
|------|------|----------|
| engineer | 局部清晰实现 | `["terminal", "file"]` |
| checker | 验证（不修复） | `["terminal", "file"]` |
| fixer | 定向修复 checker 问题 | `["terminal", "file"]` |
| reviewer | T1+ 总体验收 | `["terminal", "file"]` |
| architect | T2 跨模块规划 | `["file"]` |
| pre-checker | T1+ 方向预审 | `["file"]` |

## 编码前强制检查点

调用 `patch` 或 `write_file` 前，必须完成：

1. `search_files` 搜索目标符号的全部定义和引用
2. `search_files` 搜索同类平行实现
3. 交付输出必须包含「调用方搜索摘要」

未执行即调用修改性工具，标记 `[CHECKPOINT_MISSED]`。

## session_search 强制触发

以下场景必须主动调用 `session_search`，不得直接诊断：

1. 用户说"又出问题了"/"还是不对"/"跟上次一样"
2. 同一类错误连续出现 2 次
3. 涉及配置文件修改后解析失败
4. checker/reviewer 失败且疑似方法层错误

未搜索即给出诊断，标记 `[NEEDS_RECAIL]`。

## 交付格式

交付输出开头必须标记 ✅/⚠️/❌，包含：
1. 闭环确认（验收 → 实现位置 → 验证证据 → 状态）
2. 变更回顾（改了什么 / 为什么改 / 影响范围 / 清理调试代码）
3. 经验沉淀（可复用事实 → `memory`；流程/模式 → `skills/`；架构约束 → `SOUL.md`）

## 编码后强制验证

每次 `patch` 或 `write_file` 后，立即执行：

1. **语法检查**：`python -m py_compile` / `node --check` / 对应 linter
2. **相关测试**：`pytest -x` / `npm test`（如果有）
3. **git diff 确认**：`git diff --` 确认改动范围

验证失败 → 立即修复，不得继续下一步。T0 极速通道可只跑语法检查。

## 自动化验证优先

**原则**：用真实工具输出替代子代理主观判断。

| 验证类型 | 方式 |
|----------|------|
| 语法/编译 | `python -m py_compile` / `mypy` / `eslint` |
| 测试覆盖 | `pytest -x` / `npm test` |
| 安全扫描 | `bandit -r` / `npm audit` |
| 调用方确认 | `search_files` 搜索引用 |
| diff 范围 | `git diff --` |
| 架构合理性 | `gitnexus_impact` (已安装时) |
| 边界条件 | `execute_code` 跑边界测试 |

**规则**：T1 及以下优先跑自动化验证，不创建 checker 子代理。子代理返回空结果或明显 truncation → 直接内联执行其职责。

## 经验回写

以下场景必须回写：同类错误出现 2次及以上 / 用户明确纠正 / 新坑 / 未记录经验导致验证失败。

| 类型 | 目标 | 工具 |
|------|------|------|
| 可复用事实 | `memory` | `memory(action='add')` |
| 反模式/陷阱 | `skills/anti-patterns/` | `skill_manage` |
| 最佳实践 | `skills/patterns/` | `skill_manage` |
| 工作流改进 | `skills/workflow/` | `skill_manage` |
| 架构约束 | `SOUL.md` / `.hermes.md` | `patch` |
| 用户偏好 | `USER.md` | `patch` |

禁止编造未验证的经验。
