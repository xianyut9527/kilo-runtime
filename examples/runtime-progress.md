# 运行时进度紧凑展示示例

> 演示一种非 7 节点编排流程的「**当前任务 / 流程阶段 / 节点状态 / 完成度**」紧凑展示，供项目接入时参考。
> 状态枚举严格遵循 `.kilo/instructions/workflow-core.md` 中规定的 5 种状态。
> 节点数控制在 3-5 个（本示例取 4），并演示一次 `⏳ → 🔄 → ✅` 的完整转换。

## 一、四要素定义

| 要素 | 含义 | 典型呈现 |
|------|------|----------|
| 当前任务 | 用户最近一次提出的执行类任务名称 | 标题或首行 |
| 流程阶段 | 当前所处的整体阶段及其序号 | `阶段名 (n/N)` |
| 节点状态 | 各关键节点的实时状态 | 5 种状态枚举 |
| 完成度 | 已完成节点数 / 总节点数 + 可视化 | `N/M` + ASCII 进度条 |

## 二、状态枚举

与 `.kilo/instructions/workflow-core.md` 保持完全一致：

- ⏳ 待执行
- ✅ 已完成
- ❌ FAIL
- 🔄 进行中
- ⏸ 不适用

## 三、Markdown 表格格式

适合在文档、PR 描述、Issue 评论等支持表格的载体中展示。

**当前任务**：为 `kilo` 增加运行时进度展示

**流程阶段**：实现阶段 (2/3)

**节点状态**：

| # | 节点 | 职责 | 状态 |
|---|------|------|------|
| 1 | 需求澄清 | 与用户对齐范围与验收标准 | ✅ 已完成 |
| 2 | 单元拆解 | 划分任务单元、确定依赖 | 🔄 进行中 |
| 3 | 单元实现 | 按单元编码 + 自测 | ⏳ 待执行 |
| 4 | 整体验收 | 回归测试 + checker 验证 | ⏳ 待执行 |

**完成度**：`1/4 节点完成` · `[████░░░░░░░░] 25%`

## 四、纯文本格式

适合终端日志、单行通知、不支持表格渲染的场景。

```text
[当前任务] 为 kilo 增加运行时进度展示
[流程阶段] 实现阶段 (2/3)
[节点状态]
  1. 需求澄清   ✅ 已完成
  2. 单元拆解   🔄 进行中
  3. 单元实现   ⏳ 待执行
  4. 整体验收   ⏳ 待执行
[完成度] 1/4 节点完成  [████░░░░░░░░] 25%
```

## 五、状态转换演示

### 5.1 完整转换（必含）

以「单元实现」节点为例，演示 `⏳ → 🔄 → ✅` 完整路径：

| 时间点 | 状态 | 触发条件 / 说明 |
|--------|------|------------------|
| T1 | ⏳ 待执行 | 等待前置节点「单元拆解」完成 |
| T2 | 🔄 进行中 | 「单元拆解」已完成，开始编码 |
| T3 | ✅ 已完成 | 代码 + 自测通过，提交验证 |

对应完成度演进：

```text
T1  1/4 节点完成  [████░░░░░░░░]  25%
T2  2/4 节点完成  [████████░░░░]  50%
T3  3/4 节点完成  [████████████]  75%   ← 此处「单元实现」由 🔄 转为 ✅
T4  4/4 节点完成  [████████████] 100%   ← 整体验收通过
```

### 5.2 异常分支（FAIL）

当任一节点未通过验证时，状态置为 `❌ FAIL`，并阻止后续节点进入 `🔄`：

```text
[当前任务] 为 kilo 增加运行时进度展示
[流程阶段] 实现阶段 (2/3)
[节点状态]
  1. 需求澄清   ✅ 已完成
  2. 单元拆解   ❌ FAIL      ← checker 未通过，等待 fixer
  3. 单元实现   ⏸ 不适用     ← 前置 FAIL，本节点阻塞
  4. 整体验收   ⏸ 不适用
[完成度] 1/4 节点完成  [████░░░░░░░░] 25%  (阻塞中)
```

### 5.3 空值分支（N/A）

整个流程尚未启动或被跳过时，全部节点可置为 `⏸ 不适用`：

```text
[当前任务] (无)
[流程阶段] (未启动)
[节点状态]
  1. 需求澄清   ⏸ 不适用
  2. 单元拆解   ⏸ 不适用
  3. 单元实现   ⏸ 不适用
  4. 整体验收   ⏸ 不适用
[完成度] 0/4 节点完成  [░░░░░░░░░░░░]  0%
```

## 六、ASCII 进度条参考

固定 12 格，每格 ≈ `100/12 ≈ 8.33%`。节点数变化时按比例填充：

```text
0/4   [░░░░░░░░░░░░]   0%
1/4   [███░░░░░░░░░]  25%
2/4   [██████░░░░░░]  50%
3/4   [██████████░░]  75%
4/4   [████████████] 100%
```

> 节点数不为 4 时，建议格子数保持在 10-20 之间以维持紧凑感；完成度百分比按 `已完成/总数 × 100` 四舍五入。

## 七、接入建议

- **状态枚举**：在 `coderAgent` 的强制流程日志中复用 `⏳ ✅ ❌ 🔄 ⏸`，避免引入新符号导致与 `.kilo/instructions/workflow-core.md` 不一致。
- **完成度双呈现**：`N/M` 便于精确判断，ASCII 进度条便于人眼快速定位；两者并列展示效果最佳。
- **流程阶段**：用 `阶段名 (n/N)` 形式，阶段本身是节点的高一层抽象；N 通常 2-4，避免过细。
- **节点数控制**：3-5 个为宜；过多会破坏「紧凑」定位，过少则失去进度反馈意义。
- **FAIL 处理**：任一节点 `❌ FAIL` 时，后续节点应同步置为 `⏸ 不适用`，避免给出虚假的「进行中」观感。
