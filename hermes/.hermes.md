# 项目上下文文件（.hermes.md）

> Hermes Agent 自动发现本文件（优先级：`.hermes.md` > `AGENTS.md` > `CLAUDE.md` > `SOUL.md`）。
> 本文件是 Kilo `AGENTS.md` 的 Hermes 适配版，保留编排锚点，适配 Hermes 工具体系。

## 强制编排锚点（每个项目启动时自动加载）

1. **意图判定优先**：任何任务先判定「咨询类 / 执行类」。咨询类只分析不改文件；执行类才进入后续流程。

2. **执行类三段开场白**：意图判定 → 任务定级（T0-T3）→ 强制流程日志（≥7 节点），然后才可调用修改性工具。

3. **定级前置**：命中安全敏感关键词（user/auth/payment/wallet）→ 最低 T2。

4. **单元闭环**：T1+ 任务拆为可验证小单元，每单元独立 delegate_task（engineer 子代理）→ checker 子代理 → fixer 子代理 闭环。

5. **验收必附映射表 + 已读取文件清单**：每条验收标准 → 实现位置 → 验证方式 → 边界覆盖（正常/空值/异常）→ 状态。缺则 FAIL。

6. **SCOPE_CREEP**：checker 子代理 L2 反向核对 diff，扫描验收标准未声明的改动，命中即 FAIL。

7. **自验无效**：engineer 子代理不得自验，必须过 checker 子代理客观验证。

8. **memory / skills / 自进化合规**：任务启动加载 `MEMORY.md` + `USER.md`；方法层/需求层失败触发跨会话根因回溯（`session_search` 检索历史 + `gitnexus` MCP 验证影响面）；经验回写必须经闭环验证，禁止 LLM 自动编造规则写入长期文档。

9. **流程违规即停**：发现跳步立即标 `[PROCESS_VIOLATION]` 并暂停。

10. **临时文件**：写入 `$env:TEMP` / `/tmp/`，禁止污染项目目录。

## 子代理委派策略

通过 `delegate_task` 创建子代理，每个子代理有独立上下文 + 独立终端 + 迭代预算 50：

| 角色 | 委派时机 | toolsets | 对应 Kilo agent |
|------|----------|----------|-----------------|
| engineer | 局部清晰实现 | ["terminal", "file"] | engineer |
| checker | 验证（不修复） | ["terminal", "file"] | checker |
| fixer | 定向修复 checker 指出的问题 | ["terminal", "file"] | fixer |
| reviewer | T1+ 总体验收 | ["terminal", "file"] | reviewer |
| architect | T2 跨模块规划 | ["file"] | architect |
| pre-checker | T1+ 方向预审 | ["file"] | pre-checker |

## MCP 集成

```yaml
mcp_servers:
  gitnexus:
    command: npx
    args: ["gitnexus", "mcp"]
```

GitNexus 提供代码图谱能力：`gitnexus_context`（符号 360 度视图）、`gitnexus_impact`（爆炸半径）、`gitnexus_query`（Cypher 查询）、`gitnexus_detect_changes`（未提交改动影响面）。

## 交付格式

交付输出开头必须标记 ✅/⚠️/❌，包含：
1. 闭环确认（逐条验收 → 实现位置 → 验证证据 → 状态）
2. 变更回顾（改了什么 / 为什么改 / 影响范围 / 清理调试代码）
3. 经验沉淀（踩坑记录 / 可复用发现；命中跨会话价值 → 回写 MEMORY.md/SKILL.md）
