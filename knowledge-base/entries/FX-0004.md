# FX-0004：`options.failover` / `options.moa` 配置契约

- **标签**：failover, moa, config, provider
- **症状**：降级链或 MoA 模型清单改了却静默失效（无报错，行为未变）。
- **根因**：`options.failover` 与 `options.moa` 是**自研扩展键**，Kilo 不识别、schema 也不校验，字段名漂移不会报错。且这些键对 `@ai-sdk/openai-compatible` 是未知参数，**必须剔除后才能下传**，否则请求报错。
- **契约（W3.6 固化，勿随意改名）**：

```jsonc
"provider": {
  "hx": {
    "npm": "file:///<绝对路径>/provider/hx-failover",  // 必须 file:/// 前缀
    "options": {
      "baseURL": "...",
      "failover": {
        "cooldownMs": 60000,                 // 失败模型冷却，默认 60000
        "chain": { "models": ["模型A", "模型B"] }   // 也接受 profiles / models / 纯数组
      },
      "moa": {
        "references": ["模型A", "模型B"],       // 参考模型，上限 3
        "aggregator": "模型C"                  // 聚合模型
      }
    }
  }
}
```

- **行为**：主模型永远排在链首（无需重复写）；链去重；`failover` 缺失或为空时回退内置默认链 `glm-5.3-flash → kimi-k2.6 → deepseek-v4.1-flash → glm-5.2`；`failover.nested` 为真时**直接抛错**（legacy 禁止嵌套，防循环）。
- **验证方式**：`node -e` 直接 `import` 包并检查 `languageModel(id).hxFailoverChain`，或跑一次故障模型看是否注入 `⚠️ [failover]` 通知。
