# FX-0001：Kilo 绝不换模型

- **标签**：failover, provider
- **症状**：主模型报错（429/5xx/超时）时，Kilo 只用同一模型退避重试 5 次后中断，不会自动切换备用模型。
- **根因**：Kilo 7.6.2 内置重试逻辑：`RETRYABLE={408,409,425,429,500,502,503,504}`、`MAX_RETRIES=5`、退避 `[5,10,30,60,300]s`、`MAX_MS=3e5`，代码路径中**没有跨模型切换分支**；`QuotaExceeded=false` 时配额用尽立即失败。`small_model` 不是 fallback（只管标题/commit/prompt enhancement）。
- **修复**：自研 provider 包 `provider/hx-failover`，在 provider 层包装 `doStream`/`doGenerate`，失败时沿 `options.failover.chain.models` 切换并注入可见通知。用 `npm="file:///.../hx-failover"` 挂载。
- **关键坑**：
  - 切换通知必须用 `TransformStream` 前置 `text-start` → `text-delta` → `text-end`，三者缺一即报 `text part <id> not found`。返回 async generator 会让 Kilo 报 `A.pipeThrough is not a function`。
  - `failover` 是扩展键，须在解构时剔除，否则透传给 `@ai-sdk/openai-compatible` 报未知参数。
  - 全链失败必须抛**原始最后一个错误**，不得静默吞错（反模式 R8）。
