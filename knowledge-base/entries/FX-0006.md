# FX-0006：路径与扩展键的三条硬约束（`~` / `file://` / 自定义键）

- **标签**：config, provider, plugin, install
- **症状**（三者独立，但都表现为「配置静默失效」或「整体校验失败」）：
  1. `instructions` / `skills.paths` 里写 `~/.config/kilo/...`，注入不生效；
  2. `provider.<x>.npm` 写 `file://C:/path`，provider 加载失败；
  3. `kilo.json` 里加了 `"//": "注释"` 之类的自定义键，整份配置报 `Unrecognized keys` 直接失效。
- **根因**：
  1. **Kilo 不展开 `~`** —— 按字面量处理，`instruction_origins` 里会原样显示 `~/.config/...` 且 `trusted` 状态异常。
  2. `file://C:/path` 被 URL 解析成 **主机名 `C:` + 路径 `/path`**；必须 `file:///C:/path`（三斜杠）。
  3. 配置 schema 为 `additionalProperties: false`，任何未声明键（含 `//`）都会让**整份**配置失效。
- **修复**：
  - 路径写绝对原生形式（`C:/Users/x/...`）。Windows 的 MSYS/git-bash 里 `$HOME` 是 `/c/Users/x`，**不能**直接下发；用 `cygpath -m "$HOME"` 或手写盘符。
  - 仓库模板用占位符（本仓库用 `__KILO_HOME__`）由安装脚本替换，避免把本机路径写进版本库。
  - `npm` 固定 `file:///<绝对路径>`。
  - 字段说明写在 `plan.md`/`README.md`，**不要**写进 `kilo.json`；需要就地注释时评估迁移到 `kilo.jsonc`（schema 声明 `allowComments: true`）。
- **验证方式**：`kilo debug config` → 看 `instruction_origins` 的键是否为可解析的绝对路径，且无 `Configuration is invalid`。
