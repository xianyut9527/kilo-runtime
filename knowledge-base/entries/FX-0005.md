# FX-0005：config 权限规则是「最后一条匹配者生效」

- **标签**：permission, config, plugin
- **症状**：`permission.bash` 里写了例外规则（尤其 `deny`）却不生效；危险命令照样执行，或安全的 git 命令反而被拦。
- **根因**：实测 7.6.2：规则数组**从上到下求值，最后一条匹配的模式生效**（不是第一条）。因此配置 JSON 里的书写顺序决定结果：
  - `{"bash":{"*":"allow","git status*":"deny"}}` → `git status` 被 **deny**（例外在最后，生效）。
  - `{"bash":{"git status*":"deny","*":"allow"}}` → `git status` 被 **allow**（兜底在最后，吞掉例外）。
  - 内置技能 `kilo-config` 的文档自相矛盾（先写 "first match wins"，后写 "last matching rule wins"），**以实测为准**。
- **修复**：兜底 `*` 永远写在最前，例外规则追加在后。要叠加的例外越多，越要靠后。
- **验证方式**：
  ```bash
  # 隔离家目录下直接执行工具，看是否被拦
  USERPROFILE=<iso> HOME=<iso> kilo debug agent code --tool bash \
    --params '{"command":"git status --short","description":"probe"}'
  # 被拦时报：The user has specified a rule which prevents you from using this specific tool call
  # 报错信息里会打印完整规则数组，可直接看到命中顺序
  ```
