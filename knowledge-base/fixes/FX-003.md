## 症状

- bash 工具里 `Where-Object { ... -match/-notmatch <含 ( [ { 或 (? 字符的 regex> }` 触发 PS5.1 解析器 `ArgumentException`，错误反复重投 6000+ 行刷屏。
- 会话被这段无效输出撑爆，正常执行被淹没，上下文被大量无意义错误行污染。
- 触发本质是用正则运算符做**字面量匹配**，正则元字符未被转义导致解析/执行失败。

## 根因

PS5.1 对 `-match` 右侧含正则元字符（`(` `[` `{` `?` 等）的 pattern 解析脆弱；在 `{}` 管道块内嵌该 regex 时解析失败，异常进入重投循环。根因是**工具选型错误**——本应做纯字面量/文件级匹配，却用了正则语义运算符去匹配含元字符的字符串，属 `[PS51_REGEX_RISK]` 高危模式。

## 修复

- **首选**：改用 glob/grep/rg 工具（include 限定扩展名/路径前缀），或 L2 窄搜，避免在 bash 里写易碎的 PS5.1 regex。
- **必须用 bash+PS5.1 时**：用 `-eq`/`-like` 做字面量匹配，或把含元字符的 pattern 先存入变量再逐项比对，规避解析器在调用现场解析元字符。
- 命中该模式即标 `[PS51_REGEX_RISK]`，按 workflow-core.md §PS5.1-Regex-Safety 改写成上述安全形态。

## 复验

- 同命令改写后重跑，无刷屏、无 `ArgumentException` 反复重投。
- 等价检索用 `rg`/grep 返回与预期一致的结果集（无缺失/无多命中）。
- 日志不再被 6000+ 行错误输出撑爆，会话可正常继续。
