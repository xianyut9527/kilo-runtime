## 症状

quality-gate acceptance-check FAIL（verify_command 查旧模式 text.match 但实现已改为 firstIntInBlock 封装）+ search-discipline pattern_alternation 误报（countTopLevelPipe 把 JS 逻辑或 double-pipe 当正则 alternation 计数）。

## 根因

1. coder 每 batch 整体替换 execution.acceptance_map 数组（非 append），多单元并行后只剩最后写入的单元条目，前面单元的验收映射丢失。
2. verify_command 未随实现漂移同步：U1 从 text.match 改为 firstIntInBlock 后，acceptance_map 的 verify_command 仍查 text.match 模式。
3. countTopLevelPipe 逐字符数 pipe 未识别成对 double-pipe（JS 逻辑或），把 prose 中的 || 当正则 alternation 计数。

## 修复

1. QUALITY 前 consolidate 全部单元 acceptance_map 为一次写入（fixer 代写或 coder 补写）。
2. verify_command 用正向断言（node -e 读文件 includes 目标串），禁用负向断言（rg 期望0命中会 exit 1 误判 FAIL）。
3. countTopLevelPipe 遇 double-pipe 成对跳过不计数（s[i+1]==='|' 时 i++ continue）。

## 复验

quality-gate acceptance-check 12/12 PASS + search-discipline-check PASS + lifecycle-doctor 638 PASS / 0 FAIL / 0 WARN。
