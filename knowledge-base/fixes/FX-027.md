## 症状

- 症状

## 根因

- 工作区存在任务开始前的大量未提交改动（backend src/**、locale 术语统一、docs 等），QUALITY 阶段 reverse-auditor/reviewer 跑 git diff（worktree vs HEAD）把这些既有改动误判为本任务的 FORBIDDEN_TOUCH / SCOPE_CREEP，产出 FAIL 假阳性，触发不必要的 fixer 循环（fixer 修无可修，只能修真实小缺陷）。

## 修复

- 根因

## 复验

- subagent 以 git diff 作为「本任务改动」的判定基线，但工作区可能混入前序会话的未提交改动；未做 mtime/暂存区隔离，无法区分「本任务引入」与「任务前既有」。与 FX-026（staged/worktree 双版本）同源：工作区非干净基线。
