## 症状

- subagent 执行 batch set 后 transition_log / quality.review / dispatch_log 条目缺失
- execution.acceptance_map 变成双编码 JSON 字符串（外层引号 + 内层转义），checkAcceptanceMap 的 Array.isArray 判定失败并报 ACCEPTANCE_MAP_NONEMPTY

## 根因

- 派给 gap-fix coder 的 batch stdin 契约把数组字段写成字符串值（双编码）
- 批量覆盖前未先 get 留证，现场被覆盖后无法回溯
- 与 FX-005（同单元并行重复派发）根因不同，不可合并

## 修复

- conductor 委派前先 get 现值留证，再允许 batch 覆盖
- batch 契约中的数组字段必须以真 JSON 数组传递，禁止字符串化
- 已丢字段经用户授权后用一次性修复脚本恢复（脚本落 TEMP 目录、bash-guard 放行、锚定 dispatch_log 时间戳），并经 recover 子命令写入 recovery_log

## 复验

- delivery-audit PASS=7 FAIL=0 exit 0
- flow-audit exit 0
- Array.isArray(acceptance_map) 为 true 且 len=5
- transition_log 4 条全链完整
