## 症状

- reviewer 判 SCOPE_CREEP FAIL，但引用的是上一个任务的 plan 文件
- git diff 行数远超当前 plan 声明的范围
- 改动无法映射到当前单元，验收映射表对不上

## 根因

- 多个任务的改动叠加在同一个未提交文件上
- 审查者读了旧 plan 文件而不是 task_context 里的当前 plan
- 未区分 staged / 基线 / 当前三层 diff，把前任务的增量算进本任务

## 修复

- 审查前先 get task_context 的 plan 与 sizing.baseline 核对基线
- diff 归因用基线行数切分：前任务增量 vs 本任务增量
- reverse-auditor 交叉定证后驳回误判（本例中争议表为前任务 U3 产物）

## 复验

- 反向审计报告附「diff 混叠定证」段落
- 验收面内零缺陷，全局不变量恒定
