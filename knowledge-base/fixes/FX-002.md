## 症状

- `.agents/skills/*/SKILL.md` L150 出现 `提交` 中"交"变 U+FFFD（`提\uFFFD`），即"提交"被写成替换字符。
- PowerShell 写中文文件后出现替换字符/乱码；内容经隐式编码转换后残留 U+FFFD。
- Node 写文件未显式 `encoding` 时也产生同类编码漂移（默认随平台/环境漂移，中文被截为替换符）。

## 根因

PS5.1 `Set-Content`/`Out-File` **默认编码不是 UTF-8**（在 ANSI/GBK 或 UTF-16 之间隐式选择），中文字符经不兼容编码转换后映射成 U+FFFD（REPLACEMENT CHARACTER）。同理，Node `fs.writeFileSync(path, data)` 未显式传 `'utf8'` 时沿用平台默认编码，也会把合法中文写成乱码。根本原因是**写文件时依赖隐式默认编码**，而非显式指定 UTF-8。

## 修复

写中文文件一律**显式指定 UTF-8 无 BOM**：

```powershell
# PS7（pwsh）+ Set-Content/Out-File：-Encoding utf8（PS7 默认无 BOM）
Set-Content -LiteralPath 'file.md' -Value $content -Encoding utf8
```

```javascript
// Node：显式 encoding
fs.writeFileSync(path, data, 'utf8');
```

写完立即跑 `node scripts/scan-encoding.mjs` 验证无 BOM（EF BB BF）/U+FFFD/GBK 双字节残留。命中即修复并重写该文件。

## 复验

- `node scripts/scan-encoding.mjs` → exit 0，无 BOM/U+FFFD/GBK 残留。
- `git diff` 该文件无 mojibake 字节（无 `\uFFFD`、无 EF BB BF 头）。
- 再次读取确认中文关键词（如"提交"）可被 `rg` 正常命中且内容可读。
