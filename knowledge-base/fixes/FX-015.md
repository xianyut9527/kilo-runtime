## 症状

- 症状：改 install 排除清单（RecursiveExclude / RootOnlyExclude）后，deploy-drift-check 报出成对的假 MISSING 或假 DIFF；把清单镜像一份到 scripts/lib 作回落副本时，scripts/decouple-check 立刻对该镜像判 critical（install 侧同样的行早已豁免）；RootOnly 新增一个目录型条目（如 reports）后，其下所有文件在仓库侧被列为期望集，报假 MISSING。根因：为消除「多处手抄同一清单」而新增的 FALLBACK 镜像，本身仍是第二份清单，会同时漂两类东西——漂数据（install 加了项而镜像没跟）与漂元规则（围绕该清单的豁免表、匹配语义没跟着复制）。更隐蔽的是匹配语义：RootOnly 原本只放根级文件，set.has(rel) 精确匹配刚好够用，加入目录项后该隐含假设被打破，而 install 侧（根级命中即跳过整目录）语义是对的，构成「同一语义两处实现、只有一处对」。修复：① 让常态路径不命中镜像——按候选根依次解析（--repo 优先于脚本所在树），只有全部读不到才回落，且输出行显式打印 excludes=来源@根，出现 fallback 即异常信号；② 用 present 字段区分「无安装脚本」（部署副本正常）与「有脚本但解析不出」（必须 FAIL），禁止两者共用一个回落分支，否则 install 被改写给成静默放行；③ 匹配语义下沉为 lib 纯函数（isRootOnlyExcluded 按首段命中整棵子树、buildDriftExcludes 合并比对侧独有项、parseMdSubstDirs 作占位符替换清单的唯一解析器），使 CLI 内的关键判定可被夹具覆盖而不是只能跑整个命令；④ 镜像配交叉校验夹具，比对导出的常量而非源码文本（写法重构不会让夹具失灵）；⑤ 消费方（drift-check、command-path-hygiene）改 import 共用，删除各自的副本与硬编码正则。复验：变异测试证明夹具非装饰——把「解析不出必须 FAIL」分支短路后仅该条用例变红并给出 'PASS' !== 'FAIL'；drift-check 输出 excludes=install.ps1+install.sh@仓库根 (24 names, 5 root-only) 且 missing=0 diff=0 extra=0；仓库侧与部署副本侧 unit.executed 均为同一套用例全通过。边界：任何「为兜底而复制的清单或配置」都适用同一判据——先问常态会不会命中它，会则消灭，不会则必须让命中时可见并配交叉校验夹具。
