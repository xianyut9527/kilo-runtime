# 后端架构理解

## 目标

- 先理解服务边界、依赖方向和关键调用链，再决定改动位置。
- 避免把业务逻辑、接口适配、持久化和任务调度跨层混写。

## 执行步骤

1. 识别入口层、应用层、领域层、基础设施层或项目现有等价分层。
2. 确认目标变更应落在哪一层，并说明原因。
3. 搜索现有服务、仓储、错误类型、事件发布或任务调度实现，优先复用。
4. 若需要跨模块改动，先列出影响面和验证点，再实施。

## 输出要求

- 给出改动位置、依赖方向和影响范围。
- 若项目分层和模板不一致，以项目现状为准，不强行套模板。
